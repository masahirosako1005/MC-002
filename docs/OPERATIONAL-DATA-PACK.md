# 数か月運用の追加データ

2026-11-10。利用者から明示された、初期アカウントの記録・地図・会話・日帰り・クーポンを充実させる追加要件への架空データである。実際の来訪、観光効果、原 CSV の個人履歴を表すものではない。

## 範囲

- manifest: `operational-content-20261110-v1`、新規 ID: `ops26-`。
- 既存の架空 36 人と、初期 aoi / ren / mio ＋新しい架空の仲間 3 人を、6 人ずつの 7 組として使用。
- 過去 10 週間、週 2 日、計 140 開催・840 人回の確認済み参加。初期 3 人には各 20 回の参加、写真投稿 20 件、非公開の位置付き訪問 20 件、旅の記録 10 件。
- 既存 2 事業者に加えて 4 事業者を N西市登録設定付きで追加。12 公開プラン・12 有効クーポン・48 講、うち初期 3 人の次回予定は 6 開催。
- 初期ユーザーの投稿と講は既存の「同期の旅じたく」(`peers`) に追加。新規コミュニティは作らない。仲間の参加承諾、非公開会話、共有条件決定、事業者招待承諾、共有会話、双方の行程確認、実施の順序を記録する。
- クーポンは一人料金に対して 500 / 800 円、事業者負担、各 200 枠。確保済み・利用済み履歴は捏造しない。次回開催で実際の確保 API を使える。

## 保護と限界

既存行は更新・削除しない。既存の住所、地域共有同意、写真、資格を変更しない。新しい仲間 3 人にも住所を推測登録しない。初期 3 人の本人記録は非公開とし、写真投稿と詳細座標の共有は分離する。素材はローカル画像を EXIF 除去して使う。陶芸・庭園・川辺には 2026-11-10 生成の用途に合う素材を追加した。汎用の画像であり、実際の N西市や参加者を撮影した証拠ではない。

履歴は固定 ID と manifest により一度だけ追加する。既存の日別ポイント枠を避ける。必要なアカウントの離脱・無効化や ID 衝突を発見した場合、既存状態を復活・上書きせず停止する。DB は一つの書込トランザクションで処理し、途中失敗時は rollback する。画像の新規ファイルだけが途中失敗時に残ることはあるが、同じ内容の再試行で再利用し、既存ファイルの異なる内容は上書きしない。

市の集計は現在の本人同意を参照する。標準の初期状態では 42 人のうち住所未登録 6 人、共有済み 6 地域×6 人となる。既存の本人入力や撤回があれば正しい秘匿結果を優先し、閾値を緩めない。日付は適用日を基準に生成し、JST で計算する。フィードは主担当が追加したページ方式（初期 24 件）で古い投稿へ進める。本人の旅の記録からは追加した全訪問に到達できる。同月の記録名には月日を含め、週ごとに見分けられるようにした。

## 実行

startup からは呼ばない。schema 11 または 12 と前段の `app.enrichment` 適用済み DB が必要。DB / media をバックアップした上で、現行バックエンドと同じ `APP_DB_PATH` / `MEDIA_DIR` / `SEED_ASSET_DIR` を使い、`community/backend` を作業ディレクトリとして次を実行する。

```powershell
python -m app.operational_seed --apply
```

Python からの入口は `app.operational_seed.apply(database, settings, at=None)`。返却 manifest の件数と `already_applied` を保存する。再実行は既存 manifest を返し、日付・件数を増やさない。実 DB 投入は主担当が行う。
