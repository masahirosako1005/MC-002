# 講プロトタイプの実装範囲

2026年11月9日。設計2.6に基づくローカル操作版。事業者プラン・講の会話と条件・選択後の相談、CP25までの左右表示は確認済み。最新CP26は1440×900で上部の短い場面見出しと左旅行者/右事業者の2スマホへ整理し、中央説明・履歴・外側ボタンを廃止する変更で、更新版で画面9/9・安全性8/8を確認済み。Airbnbを第一のUI・UX参照として、写真と条件の探索、費用と行程の比較、相談を段階化する方針は維持。操作動画と新版スライドは後続で、今回は作らない。

見出しは実操作の成功イベントだけで更新する。左右の独立認証は維持し、失敗や時間経過を成功として演出しない。旧案の再生・停止・次へ・リセット・拡大と、中央支援表示の成功記録は履歴として保持し、CP26の要件や合格として流用しない。

## 体験

既存のコミュニティを選び、写真を投稿して被写体タグ候補を確認する。本人が選んだ好みと利用許可を使い、旅仲間と行き先の案を作る。一人ひとりが参加意思を返し、全員が承諾したときに講を成立させる。講では任意の協力内容と旅行計画を保存する。

LINEのグループ内の写真整理、Instagramの写真フィードから、慣れた操作の型を参考にした。生成り、落ち着いた朱色、濃茶の文字を用い、講の目的と少しずつ持ち寄る協力を独自の要素にする。PCではコミュニティ・写真・次の旅の3領域、スマホでは単列と下部ナビを使う。

## 初期データと画像

- 操作できる架空アカウントは旅行者3人と事業者2社。認証を通して切り替える。二台表示では左右が独立した短期ログインを持つ。
- 同期のコミュニティは200人の合成データ。3人で承諾まで操作できる代表シナリオと、候補人数の検証を分ける。操作できない合成会員を自動承諾させない。
- 提供された500人の個票は初期ユーザーに流用しない。架空写真や趣味を実在する個票に割り当てない。
- 山歩き、カフェ、海辺、宿でのボードゲームの写真4点を画像生成で用意した。生成方法、プロンプト、ハッシュは [画像台帳](../assets/manifest.json) に記録する。
- カタログ紹介写真は公開可能な同梱の架空素材だけを使う。利用者がアップロードした写真をカタログの配信経路へ公開しない。

## ローカルの画像分析

軽量のMobileNetV2 ONNXモデルをローカルに置き、画像の画素から被写体を分類する。ファイル名や説明文だけからタグを付けて視覚分析と称する処理にはしない。実行時に外部AIへ送信しない。

このモデルは被写体の粗い候補を補助するもので、登山をしたこと、本人が飲酒すること、特定の人物・場所・趣味を確定しない。対応しない画像や失敗時には手入力できる。本人の好みとして使うかは別に確認する。精度80%などの設計上の仮目標を達成したとは未検証のまま説明しない。
