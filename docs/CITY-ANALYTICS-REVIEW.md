# N西市統合集計の独立レビュー

2026-11-10。新しい市全体の集計 API と画面の権限・個人情報・数え方を対象にした読取レビュー。利用者が市内全事業者の集約情報を閲覧することを明示許可したため、自社外の集計そのものを権限違反とはしない。個別の商談、非共有会話、写真、住所個票の公開許可へは拡張しない。

## 結論と範囲

最終読取時点で、認証・市所属を迂回して市 API を利用する経路、他社の個票や私的な商談を返す経路、入力値による SQL 注入経路は確認していない。実装の安全性全体を保証するものではない。表示の `no_data` と少人数非表示の混同（CA-01）、全期集約のグラフが1点だけだと見えない問題（CA-03）は、担当の修正を読み取り再確認した。未解消の P1/P2 指摘はない。後述の差分推測の限界は残る。

対象は `community/backend/app/analytics/city_scope.py`、`city_privacy.py`、`city_service.py`、`city_schemas.py`、`analytics/router.py`、`city_registry.py` と main の登録箇所、`community/frontend/src/ProviderDashboard.tsx`、`ProviderTrend.tsx`、`ProviderOriginMap.tsx`、`provider-analytics-types.ts`。既存の認証、本人地域設定、自社集計、App の認証切替との境界も必要な範囲で確認した。レビュー担当によるアプリソース・実 DB の変更はない。

## 指摘

### CA-01 / P2: 0件を少人数非表示と表示する（修正確認済み）

初読時の `ProviderTrend.tsx:14` は `status !== 'available'` をすべて非表示扱いにし、`ProviderDashboard.tsx` の CityComparison も `no_data` の 0 を「非表示」と描画した。API が明示する「0」と「公開できない null」が画面で混同される。漏洩は起こさないが、利用状況の意味を誤って伝える。

最終 `ProviderTrend.tsx:79` は `no_data` を「この期間の確認済み利用はありません」と空状態にし、数値表は 0 を保持する。`ProviderDashboard.tsx:231` / `:268` は `insufficient_sample` のときだけ事業者別数値を隠す。`ProviderOriginMap.tsx` は市側母数を nullable に分け、非表示を 0 に変換しない。「匿名集計」の断定表記も取り除かれた。ソースで修正確認済み、実ブラウザー確認は主担当の別記録とする。

### CA-02 / 残リスク: 期間・取得時刻・既知情報との比較

小集団抑制は数学的な匿名化ではない。例えば 30 日と 90 日でどちらも公開可能でも、差や既知の参加者情報で追加の 1 人について推測できる場合がある。適応的な trend の区分選択や集計更新前後も情報を持つ。原子的な事業者区分の抑制は明白な自社差引きを減らすが、あらゆるクロス集計・外部知識との組合せを防ぐ保証ではない。

契約と API notes はこの限界を明記し、任意期間・個人・地域・事業者部分集合を指定する query を提供しない。本機能を一般公開用の匿名統計、差分プライバシー適合、又は匿名化認証として説明してはならない。より強い保証を必要とする用途は別の設計判断が必要。

### CA-03 / P2: 全期集約の1点が描かれない（修正確認済み）

trend が期間全体へ集約されると items は1件になる。polyline の1点だけでは線分が現れず、記録があるのに空のグラフに見える。最終 `ProviderTrend.tsx:110` は1点の circle を中央に置き、`:126` は期間と値も併記する。非表示データへ点を作らず、公開できる1区分の値だけを描く修正を再確認した。

## 適用した指針と検証の区別

- security-best-practices: FastAPI の認証/オブジェクト認可/応答制限/SQL と React の安全な文字列描画/クライアント認可の限界を適用。新市処理に HTML 挿入や外部送信を追加する必要はない。
- FastAPI: Annotated、依存による認証、専用の Pydantic 応答、入力の制限、同期 DB 処理と同期経路を確認。クラウド配備や外部 telemetry は今回のローカル要件へ追加しない。
- React: 範囲・事業者・期間によるキーの再作成、原始値依存の effect、取得の中止と古い結果の破棄を確認。読み取り時の型分離を API 契約と照合する。

実装担当の `artifacts/city-analytics/pytest.xml` を読み、専用18件、失敗0、エラー0、skip0（16.809秒）を確認した。対応する試験本文には、認可・登録撤回・同日別店・JST境界・400日前履歴・不正/未来日時・取消/証人失効・原子的事業者区分・同意撤回・適応集約・0件・個票非露出・読取不変が含まれる。自分の実行結果として数えていない。
