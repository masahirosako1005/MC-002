## 操作と保護

`python -m app.enrichment --apply` を稼働環境で明示的に一回実行する。通常の起動には組み込まない。実行前は `community/scripts/full_snapshot.py backup --allow-stop` で保存内容を確保する。

全追加IDは `extra26-`。一つのDBトランザクションで投入し、settingsに投入版/件数/基準日時を記録する。再実行は記録を返すだけで、日時の再計算、重複、既存入力の上書きを行わない。未完了の同名namespace衝突時は中止する。

画像は生成素材だけを読み、既存処理でEXIFを除去する。中断時の未参照画像は同じ内容だけ再利用し、異なる内容は上書きしない。既存データに対するDELETE/UPDATEは実施しない。

## 測定上の扱い

画面の数値は保存記録からの計算値だが、この追加分は架空の記録である。実観光客の属性・需要・再訪率や販売成果を証明しない。属性が未収集のときは推測で補わない。少人数の条件内訳を隠す基準も同じように適用する。

テスト：`test/backend/test_enrichment.py`。初回のINSERT列数不一致を検出し修正した経緯を、`artifacts/test-runs/enrichment.xml` と `enrichment-fixed.xml` に保持。既存users/posts不変、再投入不増殖、外部キー、プラン入力制約、既存利用者への加点なしを検証。
