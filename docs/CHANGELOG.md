## 発表での追跡方法

- `git log --oneline` で変更順を確認。
- `git show <commit>` でその変更の差分を確認。
- 各段階の評価は docs/EVALUATION.md、試験証拠は artifacts/ を参照。
- 仕様変更は設計書も同時に更新する。未検証・失敗・未解決を履歴から消さない。

R04では失効後の復旧を改善する途中、403を広く扱いすぎて訪問コード訂正の導線を壊した。既存試験が検知し、CSRF専用ヘッダーへ限定して修正。別ブラウザー、同じブラウザーの別タブ、古い復旧ダイアログの3経路を追加確認した。無条件の書込再送や勝手な別手帳の作成で解消したことにはしない。

ソース配布時は `scripts/package_release.py` がコミット済みファイルのみを収集し、秘密・DB・依存キャッシュの混入を拒否する。ZIPに内容ハッシュの一覧とGit履歴bundleを同梱する。PJの `.git` と、チケットのリビジョン参照からも差分をたどれる。
