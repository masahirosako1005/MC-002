# 反復評価台帳

## 運用

実装→検証→測定→課題選定→修正→再検証を繰り返す。これはPJ独自の進捗・品質指標であり、大会の公式点や実再訪率ではない。合格した証拠がある項目のみ加点。未検証は0点で分母に残す。安全性の重大問題、データ破壊、起動不能があれば総点にかかわらず提出不可。

同じ評価項目と条件で前回との差を記録する。自動テストの数を増やすだけで点を増やさない。項目・重みの変更は別版とし、旧点と直接比較しない。定量評価の下降は原因を調査・修正し、重要な仕様変更や再訪体験の取捨選択が必要な場合に利用者へ意見を求める。通常の不具合修正は自律的に進める。

効果評価は別に、操作課題の完了率、所要時間、誤操作数、次の来訪理由の理解を測定する。ユーザー試験を行っていない段階で数値を作らない。現地再訪の実測には運用期間が必要であり、ローカルデモから効果を断定しない。

追加試験の注意：browser-tests-additional-scenarios.jsonの2失敗は、失効後に新しい候補を読み込もうとした試験順と、誤答後の期待得点100（正しくは95）の不整合だった。手順を修正した。browser-tests-recovery-rate-limit.jsonの429は、同一ローカル入口から短時間に復旧試験を連続実行した結果で、実装の5回/分制限が働いたもの。保護設定を緩めず、試験間隔を1分以上あける。試験側の前提誤りを製品の機能低下と混同しない。
