# 講を使う

起動先は [講](http://127.0.0.1:8081/) 。[左右二台のスマホ](http://127.0.0.1:8081/stage)では、左を旅行者、右を事業者として同時に操作できる。旧版は8080に残している。起動が止まっている場合は [起動手順](../community/README.md) を参照。

最新の表示変更CP26をDockerへ反映し、画面9/9・安全性8/8を確認した。1440×900では上部に短い場面見出し、その下に左右2台を置き、中央説明・履歴・外側ボタンをなくした。通常Edgeの応答停止は別途CP27で調査中。

## 旅行者と事業者で相談する

1. 二台の画面を開き、左は `aoi`、右は `forest` と各パスワードを入力する。
2. 左の「講を見つける」で「関心から仲間を探す」か「仲間を選んでつくる」を選び、講の名前と招待する人を決める。本人が別アカウントで返事をするまでは参加待ち。
3. 講の「仲間と話す」で内輪の希望を相談し、「AIに相談」で「6人で2泊3日、森とカフェに行きたい」「1人3万円でプラン部分の予算」などを伝える。この案内はローカルの規則と公開プランの照合で、汎用生成AIではない。
4. 「この候補を確認・訂正する」で人数・泊数・予算の単位/範囲・希望日を自分で確定する。曖昧な数値は空欄を埋めて確認する。
5. 「行き先」で公開プランを比較する。「講に追加」→「候補を保存して講で話す」で、仲間と検討する候補として共有する。この保存では事業者は参加しない。
6. 保存した「候補の詳細を見る」で日別の行程と費用を確認し、「この行き先で事業者を招く」で相手・条件・相談文・共有範囲を確認して送る。
7. 右の「講への招待」で実際に「招待を承諾して参加」を押す。左は「講を更新」→「この講で事業者と話す」。両側の「講の共有相談」で返信できる。内輪の過去会話や写真は事業者には渡らない。
8. 右で「行程・見積をつくる」から日別行程・概算・未確認事項を提案する。双方がそれぞれ当該版を確認し、改訂すると確認を取り直す。双方確認後も外部予約は未確定。

35人・2泊・全員90万円・プラン部分へ条件を変えると、人数に対応する海辺のプランを比較できる。相談する場合は右側を海辺の学び舎へ切り替える。旅行の予定人数と、アプリで計画しているアカウント数は別に表示する。

CP26では上部の短い場面見出しだけを実操作の成功に合わせて更新する。操作は各スマホ内で行い、失敗時は画面内の案内に従う。左右のログイン状態は分けたまま、ページを読み直した場合は再ログインする。

CP28では二台の間に細い結びを追加した。相談を送ると左から右へ、事業者から返信を送ると右から左へ一度だけ流れる。待機中は静止する。ログイン前の非表示写真は読み込まない。動きを減らす設定や狭い画面では演出を止め、操作自体は通常どおり利用できる。

旧表示の「動きを止める」「両画面を読み直す」や左右の拡大、初期案の再生・停止・次へ・リセットは、最新指示で廃止する。本書の相談手順はスマホ内の操作であり、外側のボタンは使わない。

## 誕生日・記念日を登録する

本人のアイコンから自分の好みを開き、「誕生日・記念日」で月日を登録する。初期状態は自分だけ。日付の共有と、講へのプラン提案を別々に選べる。共有したくない場合も「自分だけで候補を見る」から公開プランだけを通常の候補として保存できる。

講の「記念日」には共有された日付と、提案利用を許可した今日から30日以内の候補が表示される。「あとで見る」「今回は見送る」を保存できる。候補の追加は事業者への招待や予約を意味しない。共有撤回で、その記念日だけを根拠に保存した候補は非表示になる。通常の候補として別途保存したものは残る。

## 利用した事業者について振り返る

事業者の参加承諾後、実際に旅を終えた講では「振り返り」を開く。代表者の終了申告とは別に、対象旅行者全員が利用確認と参考集計への同意を選ぶ。専用の振り返りに書いた明確な感想だけを整理し、普段の内輪会話は取り込まない。

自分の抽出結果は訂正・除外でき、発言の編集/削除や同意撤回でも集計が更新される。公開参考情報には最低件数があり、少ない場合は表示されない。これは本人申告とローカル規則による参考情報であり、実訪問の認証や会話全体を理解する生成AIではない。

## 事業者のプラン編集

「自社のプラン」→「プランをつくる」で、名前、地域、人数、泊数、価格と範囲、日別の訪問先を入力する。まず下書きに保存し、旅行者に見える表示を確かめて公開する。公開には各日の訪問先が必要。既存の相談には、選択時点の行程・費用が保存される。

## まず写真を投稿する

1. アカウント名とパスワードを入力し、藤沢 葵としてログインする。
2. 「同期の旅じたく」を選ぶ。「どんな旅をしてきましたか？」から写真を選ぶ。
3. 写真から出たタグ候補を確認し、合うものを選ぶ。候補が出ない場合も手動で選べる。
4. 公開先を確認して投稿する。
5. 本人のアイコン→「自分の好みを確認する」で、旅行で楽しみたいこととコミュニティごとの許可を選び、保存する。写真の被写体と、本人の趣味は別に扱う。

## 以前の提案・協力を使う

1. 「講を見つける」→「これまでの提案・協力を見る」→「仲間と旅を考える」を開く。
2. 目的に「軽井沢で、森とカフェをめぐる」と入れ、軽井沢の候補と3人を選ぶ。
3. 仲間の提案を作り、藤沢 葵として参加する。
4. アカウントを切り替え、高橋 蓮、小野 美緒もそれぞれ参加する。三人全員が承諾してから講が成立する。
5. 「できることを、持ち寄る」で協力内容を選ぶ。「参加を楽しむ」のままでもよい。
6. 旅の計画を開き、出発日・待ち合わせ・行程メモを保存する。

人数を5人にした場合、初期状態では条件と許可を満たす人が不足する案もある。不足を表示し、操作できない会員を自動で承諾させない。

## 写真と旅の地図を見返す

1. 写真に記録された位置を使う場合は、投稿画面で「これから選ぶ写真の位置情報を読み取る」を選んでから写真を追加する。位置を使わなくても写真は投稿できる。
2. 自分の投稿の「旅の地図に残す」から、旅の名前、都道府県、訪問日、場所を確認する。「県の目安」「写真に記録された位置」「座標を指定」を選べる。昔の写真や位置のない写真は場所を手入力する。
3. 場所名・訪問日・写真を自分だけに残すか、選んだコミュニティへ見せるかを確認して保存する。写真自体の公開先は元の投稿のままで、訪問の共有だけでは広がらない。正確な座標は他者へ表示されない。
4. 「旅の地図」で旅ごとの写真と場所を振り返り、記録を訂正・削除する。写真削除時は、その写真に紐付く訪問記録も削除される。
5. 愛知・岐阜・三重・静岡の4県で本人が確定した訪問がそろうと「東海をめぐる」を獲得する。「旅のプロフィール」で実績共有を選ぶと、同じコミュニティの人が県の一覧とバッジを見られる。「仲間の旅を見てみる」や投稿者の名前から開く。

この実績は本人の確認記録であり、物理的訪問の第三者認証ではない。候補の保存や写真を見るだけでは増えず、訂正・削除で条件を満たさなくなると獲得表示も外れる。地図は同梱の概略図で、経路案内・住所検索用ではない。

## 今回の範囲

画像の分析・記録・提案はPC内で動く。被写体の分類が難しい写真では候補が出ない、または不適切な候補が出るため、本人が確認・訂正する。タグの精度、実際の旅行成立や再訪への効果を保証するものではない。

旅行者・事業者の機能とCP26の簡潔な左右表示で、Dockerの相談往復を確認した。通常Edgeの応答停止は分離した試験環境と分けて調査する。写真の分類はPC内の画像モデル、会話の数値候補とプラン比較は明示的な規則で処理する。一般的な会話を理解する生成AI、実在施設の空席確認、予約・決済・外部送信は実装範囲に含まない。操作動画と新版スライドは後続で、今回は作らない。
