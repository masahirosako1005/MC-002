# 講を使う

起動先は [講](http://127.0.0.1:8081/) 。[左右二台のスマホ](http://127.0.0.1:8081/stage)では、左を旅行者、右を事業者として同時に操作できる。旧版は8080に残している。起動が止まっている場合は [起動手順](../community/README.md) を参照。

最新の表示変更CP26をDockerへ反映し、画面9/9・安全性8/8を確認した。1440×900では上部に短い場面見出し、その下に左右2台を置き、中央説明・履歴・外側ボタンをなくした。通常Edgeの応答停止は別途CP27で調査中。

## 旅行者と事業者で相談する

1. 二台の画面を開き、左は藤沢 葵、右は森の旅案内でログインする。
2. 左の「旅を計画」で名前を付ける。代表者だけで始めるか、既存の講から一緒に計画する人を選ぶ。
3. 「講の会話」で「6人で2泊3日、1人3万円くらいで森とカフェに行きたい」など希望を話す。
4. 「最近の会話から条件を整理」を押す。候補の数値を確かめ、人数・泊数・予算の単位/範囲・希望日を自分で確定する。
5. 条件から候補を探すか、事業者の全プランを見る。写真から詳細を開き、日別の行程と含まれる費用を比較する。
6. 「共有する内容を確認」から相談文を入力し、相手と共有内容を確認して送る。ここで初めて右側の事業者に相談が届く。
7. 右の「届いた相談」→「更新」で相談を開き、返事を送る。左で相談を開くと返事を読める。開いたままの会話は一度閉じて開き直すと最新になる。

35人・2泊・全員90万円・プラン部分へ条件を変えると、人数に対応する海辺のプランを比較できる。相談する場合は右側を海辺の学び舎へ切り替える。旅行の予定人数と、アプリで計画しているアカウント数は別に表示する。

CP26では上部の短い場面見出しだけを実操作の成功に合わせて更新する。操作は各スマホ内で行い、失敗時は画面内の案内に従う。左右のログイン状態は分けたまま、ページを読み直した場合は再ログインする。

旧表示の「動きを止める」「両画面を読み直す」や左右の拡大、初期案の再生・停止・次へ・リセットは、最新指示で廃止する。本書の相談手順はスマホ内の操作であり、外側のボタンは使わない。

## 事業者がプランを公開する

「自社のプラン」→「プランをつくる」で、名前、地域、人数、泊数、価格と範囲、日別の訪問先を入力する。まず下書きに保存し、旅行者に見える表示を確かめて公開する。公開には各日の訪問先が必要。既存の相談には、選択時点の行程・費用が保存される。

## まず写真を投稿する

1. 藤沢 葵を選んでログインする。
2. 「同期の旅じたく」を選ぶ。「どんな旅をしてきましたか？」から写真を選ぶ。
3. 写真から出たタグ候補を確認し、合うものを選ぶ。候補が出ない場合も手動で選べる。
4. 公開先を確認して投稿する。
5. 本人のアイコン→「自分の好みを確認する」で、旅行で楽しみたいこととコミュニティごとの許可を選び、保存する。写真の被写体と、本人の趣味は別に扱う。

## 三人で講を作る

1. 「講を見つける」→「仲間と旅を考える」を開く。
2. 目的に「軽井沢で、森とカフェをめぐる」と入れ、軽井沢の候補と3人を選ぶ。
3. 仲間の提案を作り、藤沢 葵として参加する。
4. アカウントを切り替え、高橋 蓮、小野 美緒もそれぞれ参加する。三人全員が承諾してから講が成立する。
5. 「できることを、持ち寄る」で協力内容を選ぶ。「参加を楽しむ」のままでもよい。
6. 旅の計画を開き、出発日・待ち合わせ・行程メモを保存する。

人数を5人にした場合、初期状態では条件と許可を満たす人が不足する案もある。不足を表示し、操作できない会員を自動で承諾させない。

## 今回の範囲

画像の分析・記録・提案はPC内で動く。被写体の分類が難しい写真では候補が出ない、または不適切な候補が出るため、本人が確認・訂正する。タグの精度、実際の旅行成立や再訪への効果を保証するものではない。

旅行者・事業者の機能とCP26の簡潔な左右表示で、Dockerの相談往復を確認した。通常Edgeの応答停止は分離した試験環境と分けて調査する。写真の分類はPC内の画像モデル、会話の数値候補とプラン比較は明示的な規則で処理する。一般的な会話を理解する生成AI、実在施設の空席確認、予約・決済・外部送信は実装範囲に含まない。操作動画と新版スライドは後続で、今回は作らない。
