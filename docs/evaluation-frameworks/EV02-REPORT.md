## 改善と最終証拠

UI・バックエンド・独立評価を分担し、主担当が実装根拠と統合結果を確認した。個別記録は同フォルダのEV02-UI-REVIEW、EV02-BACKEND-REVIEW、EV02-INDEPENDENT-REVIEW、EV02-STATIC-REVIEW、EV02-ACCOUNT-SECURITY、EV02-DEPENDENCIES。

### 実装した改善

- 操作：独自選択肢のTab/Shift+Tabと先頭文字検索、明示ラベル、未保存プランの継続/破棄確認、入れ子のEscape制御を整備。事業者切替後に古い取得結果を表示しないようにした。
- 認証：本人によるパスワード変更、成功時の本人の全ログイン失効、Stage再認証時の旧token失効を追加。現在値の検証中に変更/失効された場合は再確認して拒否する。他の利用者のログインは維持する。
- パスワード：scryptを32MiBの固定コストへ強化し、旧形式は正しいログイン時だけ移行。46,825件の固定ローカル候補一覧で弱い新規値を拒否。Unicodeの長さをUI/APIで合わせ、入力値を正規化したりログへ出したりしない。
- 保存・入力：画像書込みを排他作成/flush/fsyncまで行い、失敗時の取消を検証。同意は本物のJSON booleanだけを許可。本文受信の総時間上限と不正Unicode拒否を追加した。
- 保守：上書き済みCSS8ブロックと単純な状態通知の表現を整理。共通試験DBは実KDFで作成したテンプレートから毎試験複製し、テスト間のデータ混在を避けた。
- 依存：実行コンテナのpipを26.2へ更新。実コンテナの全17 Pythonパッケージ再監査で既知指摘0。frontend/browserのnpm監査も各0。OS全体の安全保証ではない。
