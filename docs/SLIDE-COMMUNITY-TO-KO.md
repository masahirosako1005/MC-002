# PowerPoint 1枚の作成指示書：CSVから「コミュニティ → 講」への設計

作成日：2026年11月10日。成果物は本Markdown。PowerPointはこの内容をもとに別途作成する。

## 1. この1枚で伝えること

**「一緒に楽しむ体験」と「場所・移動の情報」に着目し、関心を共有するコミュニティから、今回の旅を一緒に計画する少人数の講へ進む仕組みを提案した。**

聞き手には「データから着目点を選び、それを二段階の仕組みにした」と理解してもらう。CSVからコミュニティや講の必要性が証明された、という説明にはしない。

本資料の「講」は、この製品での「共通の目的のために集まり、少しずつ協力する仲間」という意味。歴史上の制度の再現を説明するスライドにはしない。

## 2. スライドに載せる文言【確定原稿】

以下の本文と脚注だけをスライドへ載せる。制作指示や後述の解説を画面へ追加しない。

### タイトル

**交流と旅先への関心を、次の旅行計画につなぐ**

### 左：CSVで分かったこと

小見出し：**アンケートの事実**

**旅で良かった点**

- 同行・交流　**69人／24.0%**
- 自然・景観　**65人／22.6%**

**要望欄で言及されたテーマ**

- 案内・地図・移動経路　**94人／32.8%**
- 施設・店舗・スポット　**72人／25.1%**

### 左から右への橋渡し

小見出し：**設計で着目したこと**

**一緒に楽しむ体験 × 旅先・移動の具体情報**

矢印のラベル：**この着目点を仕組みにする**

### 右：提案する二段階の仕組み

小見出し：**設計提案**

**コミュニティ｜関心を共有する場**

写真や体験を共有し、共通の「やってみたい」を見つける。

↓ **今回の目的・日程が合う人が、参加を選ぶ**

**講｜今回の旅を一緒に進める仲間**

少人数で行き先・日程を決め、調べる・手配するなどの協力を持ち寄る。

### 下部の具体例

**例：景色の写真を共有 → 「次は川沿いを歩きたい」 → 日程が合う人で講をつくり、行き先を相談**

### 脚注

提供サンプルの参加後回答者287人を集計（未回答213人を含まない）。要望欄は複数テーマへの言及数で、改善要求人数ではない。仕組みは設計提案で、需要・再訪効果は未検証。

## 3. レイアウトと見せ方

- 16:9の横長、1枚。タイトルは上部に1行、必要なら意味の切れ目で2行まで。
- 左側約38%にデータ、右側約54%に二段階の仕組みを置く。間の約8%は矢印と余白にする。
- 「設計で着目したこと」は左右の本文の上に細い帯として置く。データと提案のつながりを一文で先に読めるようにする。
- 右側は上にコミュニティ、下に講。二つを同じ大きさの無関係なカードとして横に並べず、幅広い関心の共有から今回の活動単位へ進む関係を示す。
- コミュニティは複数の小さな人物と写真枠、講はその中の数人と小さな行程表で表す。人数は説明用の図であり、最適人数や実データの人間関係を表さない。
- 上段から下段へつなぐ線に「本人が参加を選ぶ」ことが分かる短い文言を置く。人が自動的に振り分けられた図にはしない。
- 下部に具体例を1行、最下部に脚注を2〜3行。具体例は架空の利用場面で、CSV中の実際の行動ではない。
- タイトル32〜36pt、主要見出し24〜28pt、本文20〜22pt、脚注14〜16ptを目安にする。収まらない場合は本文を短縮し、文字を過度に小さくしない。
- 背景は明るい生成り、本文は墨色。データ側は落ち着いた青緑、提案側は控えめな朱を使い、色と見出しの両方で「事実」と「提案」を区別する。
- 講の見出しに小さな朱印風の囲みを使ってよい。背景の紙模様・巻物・挿絵は情報を覆わない程度に抑える。数値や脚注へ装飾書体を使わない。
- 添付の棒グラフ全体は貼らない。この1枚では4つの数値を抜き出し、概念へ至る道筋を主役にする。元の全分類は分析報告へ残す。

## 4. 発表時の説明原稿

> アンケートでは、旅で良かった点として、同行や交流が69人、自然や景観が65人でした。要望欄でも、案内や移動経路、施設やスポットが多く話題に上がっています。そこで私たちは、人と楽しむ体験と、具体的な旅先の情報をつなぐことに着目しました。まずコミュニティで写真や体験を共有し、共通の「やってみたい」を見つけます。その中から、今回の目的や日程が合い、参加を希望する人でつくるのが「講」です。関心を共有する場と、実際に旅を計画する単位を分けることで、次の旅行へ進める仕組みを提案しました。

この原稿は説明用。全文をスライドに貼らない。

## 5. 「なぜコミュニティだけでなく講なのか」への答え

**コミュニティは関心を共有する広い場、講は今回の目的・日程で動く小さな単位だから。**

同じ関心を持つ人でも、毎回の目的・予定・参加意思まで同じとは限らない、という設計上の前提を置く。そのため、コミュニティ全員を旅行へ参加させず、その回の参加希望者で講をつくる。さらに行き先・日程・任意の協力を決め、共有から計画へ進める。

「全員の予定が合わないことがCSVで判明した」とは説明しない。この二段階は、ユーザーから指定された共同体験・仲間選びの構想を、アンケートの着目点と接続した設計案である。

写真共有を採用したのは、景観や体験を共有する方法としての製品判断。CSVに写真データや写真共有の希望があったという意味ではない。少人数や役割分担も同様に、最適性が実証された設定ではない。
