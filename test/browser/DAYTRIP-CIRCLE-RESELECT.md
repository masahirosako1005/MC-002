# 開催作成の講再選択・回帰確認

2026-11-10。対象：`frontend/src/Daytrip.tsx` の `CreateOuting`。

## 原因と修正

すでに選択している講を選び直すと、講IDは同じまま参加者情報を破棄して読み込み中へ戻していた。講IDに依存する取得処理は再実行されず、待機表示が残る。

同じ講IDの選択は状態を変更せず終了する。選択メニュー自体は既存Choiceの処理で閉じる。異なる講を選んだときだけ、参加者・先達・事業者利用の選択を破棄して読み直す。

## ブラウザーで確認する観点

| 操作 | 期待結果 |
|---|---|
| 代表者が日帰りの開催作成を開き、読み込み済みの講を再選択 | 開催名・参加者・先達の欄が維持され、待機表示へ戻らない |
| 一部の参加者チェックや先達を変更後、同じ講を再選択 | 操作中の選択内容を維持する |
| 参加者の読み込み中に同じ講を再選択 | 進行中の読み込みが完了し、参加者が表示される |
| 別の講へ変更 | 以前の講の参加者を破棄し、新しい講の参加者と先達を読み込む |
| 「講を選ぶ」の未選択へ戻し、再び講を選ぶ | 未選択中に古い参加者が見えず、選び直した講の読み込みが完了する |
| キーボードで現在の講を再選択 | 選択メニューが閉じて操作元へ焦点が戻り、作成内容を維持する |
