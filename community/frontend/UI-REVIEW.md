# 三役の画面・操作レビュー

2026年11月9日。実装段階の記録。型検査・ビルド成功と、実ブラウザーでの合格を区別する。

## 基準と適用

Airbnbの[日本語トップ](https://www.airbnb.jp/)でロケーション・日付・旅行者をまとめる入口、[共同ウィッシュリスト](https://www.airbnb.com/help/article/1236)で候補・メモ・人数/日程を共有する行動を確認した。講では人数・泊数・予算単位・予算範囲をまとめ、行程と事業者相談の間に共有確認を置く。ロゴ・ブランド色・画面そのものは複製しない。

emil-design-engを適用し、150ms前後の反応、操作中/選択/フォーカス/空状態、44pxの操作対象、reduced-motionを共通化。security-best-practicesに基づき、通常Cookie認証と舞台Bearer認証を分離し、HTML直挿し・外部素材通信・ブラウザー保存領域への認証情報保存を避けている。

## Before / After / Why

| Before | After（実装した変更） | Why（狙い・確認すること） |
|---|---|---|
| 写真フィードと少人数の講が中心 | 「記録・旅・講」の主要入口。事業者は別の仕事場 | 記録から実際の旅行条件と地域の相談先へつなぐ |
| 旅行の例を1枚で紹介 | 大きい写真の主候補＋比較候補、日別行程の詳細 | 一覧の魅力と比較の読みやすさを両立。均一なカード列を避ける |
| 費用の目安だけを表示 | 1人/全員、プラン部分/旅行全体、概算の範囲を併記 | 比較できない費用を同条件に見せない |
| 希望は任意のメモ中心 | 会話→数値候補の確認→代表者が条件を確定 | 数値抽出を本人の意思・一般的な会話理解と混同しない |
| 標準プルダウンが混在 | 全画面で共通Choice部品。矢印/Home/End/Enter/Escape対応 | 画面の統一とキーボード操作。ブラウザー実機でフォーカス順を確認する |
| 事業者への接続なし | プラン詳細→共有内容→明示送信→個別相談 | 内部会話や元写真を自動で事業者へ流さない |
| 役割保存で講の部品を再生成 | 安定した部品ID、未保存入力を保持したサーバー更新 | 開いていた行程と保存完了表示が失われない |
| 同一画面のログイン切替 | 舞台は左右独立したメモリーBearer、Cookie送信なし | 同一originのCookie共有により左右の利用者が混ざらない |
| 舞台用の固定シナリオなし | APIの実成否イベントを中央へ表示 | 操作成功を時間だけで作らない。private本文/tokenは舞台親へ送らない |
| 通常の認証画像URL | 舞台だけ認証fetch→JPEG確認→blob表示→破棄 | img要素がCookieへ依存する問題を避ける |

## 結合QA後の改善1

根拠画像：`community/artifacts/marketplace-browser/stage-initial.png` と `failure.png` を目視確認。左右独立ログイン・認証画像・会話条件・明示共有・事業者返信は親担当の実操作で成功。選択メニューのラベル検出で停止しており、全面合格ではない。

| Before（画像/失敗で確認） | After（修正した内容） | Why |
|---|---|---|
| Choiceのラベルに選択肢の文字列が混在 | 外側ラベルの本文を明示aria-labelにし、現在値をaria-describedbyで分離 | 「予算の単位」の操作対象を一意にし、読み上げで値も伝える |
| 所属のない事業者にも「選んでください」 | 事業者名を上部に表示し、不要なコミュニティ選択と投稿を除去 | 無効な選択操作を減らし、誰の仕事場か明確にする |
| 事業者画面で写真が画面のかなり下 | 見出しを「旅のプランと相談」に短縮、前書き撤去、タブと作成行を圧縮 | 最初にプラン写真と公開状態が見えるようにする |
| 旅行者は記録から開始し、探索には長い導入 | 舞台の旅行者は旅探索から開始。人数・泊数・予算の検索ピル、短い見出し、コンパクトな計画切替 | 初めの画面で目的と候補写真を確認できるようにする |
| 画面内に大きい色面・説明が重複 | 白に近い暖色、薄い境界、写真と価格を主役にする | 暖かさを残しつつ比較に必要な情報の強弱をはっきりさせる |
| 案内役が写真由来の好みをこの推薦で直接使うように読める | 「人数・泊数・予算と、選んだ関心」へ訂正 | 現在の条件照合が実際に参照する範囲を超えて説明しない |

制作側の「デモ・試作・模擬・ローカルの企画素材」等を公開画面へ置かない。概算費用・予約未確定・共有先等の判断に必要な案内は保持する。修正後のスクリーンショットと再実行結果は親担当の次回QAで記録する。

## 結合QA結果：9項目成功

親担当による三役ブラウザー検証は **9/9成功**。検証対象の配信JSは `index-B7eq8CbM.js`。結果は `community/artifacts/marketplace-browser/results.json`、アクセシビリティ自動検査は `axe-stage.json`、画像は同フォルダーに保存されている。途中の試験失敗は、複数相談の対象指定・保存完了待機を修正して再実行し、通過を確認した。

確認した範囲：

- 左右スマホの独立ログイン、Cookie非共有、認証付き投稿写真のblob表示。
- 講の会話から未確定の数値候補を抽出し、本人の確認後に旅行条件を保存。
- 6人2泊・1人予算と35人・全員予算での候補比較、不適合理由、事業者一覧からの選択。
- 共有確認前に事業者へ相談が作られないこと、明示送信、事業者の実返信と旅行者の閲覧。
- 事業者の下書き作成・日別行程・公開。下書きを旅行者一覧へ出さないこと。
- 左右を含むaxe自動検査0件、幅390/320px・文字200%で横はみ出しなし、Choiceのキーボード操作、reduced-motion、外部通信0件。

`mobile-390.png`を独立目視した。短い見出し・条件検索ピル・計画操作の直後に大きい写真が現れ、初期版の長い前書きで写真が下へ押し出される状態を改善している。価格は金額/人数単位と費用範囲が分かれており、下部ナビは文字付き。全体の暖色と余白を保持している。

最後のソース変更は、事業者の相談一覧を同じプラン名の重複から「人数・泊数・希望日＋共有相談文の冒頭」へ変更し、両側の相談行へ `data-consultation-id` を追加したもの。内部の計画名や会話を追加共有する変更ではない。この変更を含む最終ビルドを作成し、以後ソースを固定する。

**未実施：実利用者による使いやすさ調査、旅行成約・実旅行・再訪効果の測定、網羅的なWCAG適合審査。** 自動検査0件や操作試験9件の成功を、これらの達成と扱わない。

## 舞台の簡素化：操作動画に向けた構図

利用者の最新指定により、舞台の役割を「左右の実操作が見える、余計な情報のない構図」へ変更した。今回は動画を作成していない。

| Before | After | Why |
|---|---|---|
| 左右スマホの間に案内役、説明、工程、履歴 | 左旅行者・右事業者の2台だけを中央配置 | 操作そのものに視線を集める |
| 上部タイトルと操作ボタンが複数 | 上部は小さい講の印と場面を示す短い一文のみ | 録画時の不要な説明・操作を取り除く |
| アプリをひらく、動きを止める、読込、拡大操作 | 外側の操作部品を撤去 | 舞台内のアプリ操作だけを残す |
| ログイン・閲覧でも説明や履歴が更新 | 条件整理/確定・候補比較・相談送信/返信等の実成功だけで一文を更新 | 場面の特徴を保ち、GETや失敗で成功を演出しない |
| 3列で端末の外に長い情報列 | 1440×900で2台全体を収める高さ、中央に広い余白 | 後の操作動画で左右の画面を同時に見せる |

通知は引き続き同一origin・左右iframeのsource・イベント型のallowlist・success状態を確認。本文・認証情報は受け取らず、`.stage-caption` の `data-event` に最新の主要成功種別だけを記録する。初期値は `initial`。失敗・ログイン・閲覧では現在の場面を変更しない。再現性のない自動再生や成功の捏造は追加していない。

この変更の対象は `Stage.tsx` と `stage.css`。旅行者/事業者アプリ内の操作と独立認証には変更を加えていない。前節の9/9は変更前の舞台を含む結果であり、新構図・通知の確認は親担当の更新済みQAで行う。

主担当の追加レビューで `api.ts` の条件整理/候補/選択通知をPOSTに限定した。更新版は `index-C1RUB-yC.js`。Docker上で画面9/9・安全性8/8が成功し、1440×900の全体表示を目視確認した。新しい構図の画像は `community/artifacts/marketplace-browser/stage-overview-final.png`。通常Edgeの応答停止は別途CP27で調査中で、検証ブラウザー成功を解決扱いしない。
