# 講の参加・共有相談・入力入口のレビュー

2026-11-09。静的レビューの指摘と修正確認。実API・画面の合否は同フォルダの試験結果に分ける。

| Before | After | Why |
|---|---|---|
| 既存の計画では新しい事業者招待が待機中でも旧選択APIを呼べた | 新招待の利用履歴がある計画では旧選択経路を拒否 | 事業者本人の承諾を迂回しない |
| 新招待と旧相談の終了状態が別に更新され得た | 取消・終了を両経路で連動し、共有会話への権限を再確認 | 終了後の閲覧・投稿を防ぐ |
| 対話の曖昧な数値が次の発話や確認フォームで旧値に戻り得た | 曖昧な項目を除去し、画面は空欄で本人の入力を求める | 推定を合意済み条件に変えない |
| 同文を再発言すると古い冪等キーが残り得た | 成功後に対話のキーを更新 | 新しい会話の文脈を反映する |
| 既存の成立講と一部会員の旅行計画が接続されていると他会員が開けなかった | 本人が参加済みの計画だけ再利用し、未接続者は自身の成立講から接続 | 承諾状態と権限を維持する |
| 見積の確認が役割表示だけだった | 版と確認者名・日本時間の日時を表示 | 誰がどの内容を確認したか判断できる |
| ログイン入口にアカウント一覧と既定値があった | 空欄のアカウント名・パスワード、表示切替、Enter送信 | 一般的な入力形式と独立した認証を維持する |
| 新入口の末尾の文字が3.95:1だった | 文字色を濃く修正 | 読みやすさを保つ。初回不合格はlogin/contrast-failure.jsonに保持 |

主担当は旧APIの制御、参加条件、対話フォーム、共有見積の状態、実DB移行の証拠を確認。独立レビュー担当はプロフィール・非公開会話・本人承諾・改訂版の境界を確認した。固定C1の全面合格や通常Edgeの応答停止の修復を意味しない。
