# tang you chi

四季の謎解きと旅の記録から、次に訪れる理由を残すスマホ向けWebアプリ。

React / TypeScript、Python / FastAPI、SQLite。Docker上で動作し、通常利用では外部API・外部DB・クラウド・外部素材配信へ接続しません。

## 起動

初回の依存・コンテナイメージ取得にはネットワークが必要です。WSL2とDocker Desktopの導入記録は [環境手順](docs/SETUP.md) を参照してください。

```powershell
docker compose up --build -d
docker compose ps
```

同じPCで http://localhost:8080 を開きます。停止は `docker compose down`。保存データは名前付きvolumeに残ります。`down -v` はデータを削除するため通常手順では使用しません。

初期設定はPC内だけに公開します。スマホ実機でLAN接続する場合は、公開IP・許可Origin・通信の保護を確認して設定を変更します。スマホ向け表示はPCのブラウザーでも確認できます。

## 体験の流れ

1. 「四季の謎をひらく」から四季の水門へ進み、[現地しおり](docs/FIELD-GUIDE.md)の訪問コードを入力。
2. 現在の季節の謎を選択。三つの水門を操作し、必要に応じてヒントを読む。
3. 達成した実績を旅の手帳で確認し、次の季節の体験を保存。
4. 「次の旅」で会議館からの空き時間と関心を選び、往復・体験・余裕時間に収まる候補を探す。
5. 神社の節目や海辺の四季から、行きたい体験を保存。予定は訪問履歴と分けて管理。

季節外の謎は紹介と保存ができますが、挑戦はその季節になってからです。現在季節の周遊候補は営業時間も確認するため、夜間は候補が出ないことがあります。別の季節の候補は将来の計画として表示します。

## 手帳を引き継ぐ

ヘッダーの「引き継ぎ」から合言葉を発行し、自分で安全に保管します。別ブラウザーでその合言葉を入力すると同じ手帳を開けます。再発行すると以前の合言葉は無効になります。復旧すると以前のログイン状態は無効になります。

合言葉は本人の手帳にアクセスできる秘密情報です。URLやソースへ貼り付けず、第三者に共有しないでください。サーバーには合言葉のハッシュだけを保存します。端末を変えても、同じローカルサーバーとDBへ接続する必要があります。

## 検証

```powershell
./.venv/Scripts/python.exe -m pytest backend/tests -q
./.venv/Scripts/python.exe -m unittest discover -s scripts -p test_samples.py -v
npm.cmd --prefix frontend run build
```

Docker起動後、`qa` フォルダで `npm ci`、`npm test` を実行すると、インストール済みのMicrosoft Edgeでブラウザー検証を行います。必要なQA依存は初回のみネットワークから取得します。

評価の合否・未検証・点数の変化は [評価台帳](docs/EVALUATION.md)、修正の理由とリビジョンは [変更履歴](docs/CHANGELOG.md) に記録します。自動検査の成功だけで、WCAGやASVS全体への適合を宣言しません。

## 開発チケット

[ローカル作業ボード](outputs/project-board.html)を開くと、要件・不具合・受入条件・証拠・Gitリビジョンを確認できます。PythonでJSON台帳と追記履歴を管理する独自のローカル方式です。JiraやLinearとの接続はありません。[更新手順](project/README.md)に沿って起票・状態変更します。

## 保存・復元

DBは `/app/data/journey.db`。稼働中の整合したバックアップを作る例：

```powershell
docker compose exec app python -m app.backup /app/data/backup-01.db
docker compose cp app:/app/data/backup-01.db ./data/backup-01.db
```

復元時はアプリを停止し、バックアップの整合性を確認してから新しい保存先で起動します。詳細は [バックエンド運用説明](backend/README.md)。DBと復旧情報を含むバックアップは個人データとして保護し、Gitには追加しません。

## 提供データとモデル都市

提供CSV5ファイルは参照専用で、氏名・連絡先等を出力しない分析取込を行います。アプリの架空都市の利用者へ元データの履歴を割り当てません。元データ不変、再取込の重複防止、取込結果は [データ品質記録](docs/DATA-QUALITY.md) で確認できます。

製品名と「平城京市」は正式表記確認前の名称です。水門・桜社・凪の海辺・国際会議館は本プロジェクトで設定した舞台であり、実在の奈良や施設の営業案内ではありません。既存スタンプラリーのソース・APIが未提供のため、本成果物は接続境界を分けた単独動作版です。

印刷コードの入力は強い現地所在の証明ではありません。実地運用での不正防止、既存会員との接続、実際の再訪率・地域経済効果は別途検証が必要です。

## 提出用の配布物と変更履歴

`outputs/tang-you-chi-source.zip` はコミット済みソース、設計・関連文書、プレゼン、検証証拠とGit履歴をまとめた配布物です。実行中の手帳DB、復旧コード、提供CSVの個票、依存キャッシュは含めません。展開後に上記Docker手順で新しいデータ領域から起動できます。

ZIP内の `release-manifest.json` に各ファイルのSHA-256と元のコミットを記録します。履歴を別の作業場所でたどる場合は、Gitで `git clone history.bundle review` として復元できます。このPCで新しいチェックアウトを作る場合もPJフォルダ内へ置いてください。配布の再生成は、変更を確認してコミットした後に `.venv/Scripts/python.exe scripts/package_release.py` を実行します。

修正後はAPIと該当画面の回帰試験を行い、依存更新時は監査を再実行します。DBの変更は版を追加して移行前バックアップと復元試験を行います。採点基準と未検証条件を途中で消して点数を上げる運用はしません。
