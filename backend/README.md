# Pythonバックエンド

FastAPI、SQLiteを使い、実行中の外部通信は行わない。基本API契約は `../docs/API.md`、収集機能の追加契約は `../docs/COLLECTION-API.md`。ソース・保存先・バックアップはPJ内で管理する。

## 起動と試験

PJルートから依存を導入する。

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
```

`backend` を作業フォルダとして実行する。

```powershell
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
..\.venv\Scripts\python.exe -m pytest -q tests --basetemp .backend-test-tmp
```

Dockerの入口も `app.main:app`。静的ファイルは `STATIC_DIR` 指定時だけ配信する。単一プロセスのローカル用途を前提とし、認証情報・訪問・採点・保存はサーバー側で管理する。

| 設定 | 既定・意味 |
|---|---|
| `APP_DB_PATH` | `backend/data/journal.sqlite3`。Dockerではvolume配下の絶対パス |
| `APP_ALLOWED_ORIGINS` | `http://localhost:8000,http://127.0.0.1:8000`。パスなしのオリジンをカンマ区切り |
| `STATIC_DIR` | 未指定では静的配信なし。指定フォルダのみ配信 |
| `APP_COOKIE_SECURE` | `1`でSecure属性。既定はローカルHTTP向けに無効 |

Hostも許可オリジンのホスト・ポートへ限定する。端末へのLAN公開や別ポートの開発時は、接続先を明示して設定する。CORSは許可しないため、開発時もフロントエンドの `/api` プロキシから同一オリジンで利用する。書込要求はOrigin、JSON Content-Type、セッション、CSRFを検証する。新規セッションだけCSRFの例外だがOrigin/JSONの検証は省略しない。

## API一覧

共通接頭辞は `/api`。本人の記録はCookieセッションで限定し、クライアントが所有者IDを指定するAPIは設けない。

| メソッド・パス | 内容 |
|---|---|
| `GET /health` | DB接続の稼働確認 |
| `POST /session`、`GET /session` | 手帳を開く・現在の接続情報を取得 |
| `POST /recovery`、`POST /session/recover` | 復旧コード発行・同じ手帳へ復旧 |
| `GET /catalog` | 場所・体験・問題の公開一覧 |
| `GET /journal` | 本人の訪問・挑戦・実績・保存候補 |
| `POST /visits` | 現地コードによる当日の訪問記録 |
| `POST /attempts`、`POST /attempts/{id}/hint`、`POST /attempts/{id}/answer` | 問題開始・ヒント・サーバー採点 |
| `GET /leaderboard` | 同じ問題版の最高点比較 |
| `GET /recommendations` | 時間・季節を使った候補抽出 |
| `POST /plans`、`DELETE /plans/{id}` | 次の旅の候補保存・削除 |
| `GET /collection` | 本人の全年度の証拠から12種類・3セットの収集状況を導出 |
| `PUT /collection/target` | `{trophy_id: 固定ID または null}` で次に狙う1点を保存・解除 |

収集機能のGETはDBを変更しない。PUTは認証・CSRF・Origin・JSONと固定ID許可リストを検証する。既存の `/journal` の応答形式は変えない。

## データ・時計・採点

- `users/sessions`：匿名の手帳。Cookieは推測困難なランダム値、DBにそのSHA-256のみを格納。CSRFはサーバー保管の同期トークン。セッションは180日。
- `recovery_codes`：本人が発行した256bitの復旧コードのSHA-256だけを格納。生コードは発行時の応答で一度だけ表示し、再取得はできない。再発行は旧コードを無効にする。期限はセッションと独立し、再発行まで有効。別ブラウザーやCookie消去・期限後に復旧すると新しいセッションを発行し、以前の全セッションを無効にする。コードを知る人は手帳を開けるため、公開・共有・URLへの付加は禁止。コード自体を失った場合の本人確認/サポート復旧は未実装。
- `spots/experiences/games`：架空都市の設定。実在施設の営業情報ではない。公開APIに訪問コードや正答を含めない。
- `visits`：利用者・スポット・日本時間の日付ごとに一件。同じ日の再操作を再訪件数として増やさない。印刷コードは共有可能なため、GPS・本人性・実在の来訪を強く証明する仕組みではない。
- `attempts`：現季節・年度・難易度・問題版を固定。開始と回答時に当日訪問を確認。未完了の同じ問題は再利用、完了後は新たに挑戦可能。時刻を変えるHTTPパラメーターはない。
- `achievements`：訪問実績とゲーム実績を区別。訪問は場所・季節・年度で一つ、謎解きは問題版ごとに一つ。再挑戦・再送でも実績は増えない。訪問または完成記録との更新は同じトランザクション。
- `plans`：体験・利用者ごとに一件。保存時の名前と理由を保持。保存・削除は訪問/ゲーム達成/実績を変更しない。通年の人生行事は本人の任意選択で、履歴から妊娠・家族構成を推定しない。
- `collection_preferences`：本人が選んだ次のしるしを1件保存する。獲得前・獲得済みのどちらも選択でき、nullで解除する。復旧コードで同じ手帳へ戻った後も保持する。

収集機能は場所4種、季節の水路4種、続く旅4種の計12種類。続く旅は同じ場所の別日訪問、海辺の季節、会議館訪問後の別日の訪問、異なる季節の上級問題達成を段階で集める。`app/collection.py` の固定定義v1と保存済みの訪問・ゲーム完了から導出し、現年度のカタログ外の証拠も使う。取得日は条件を初めて満たした証拠日時を返す。セット完成で返す称号は金銭・割引特典ではない。

訪問は同じ季節・同じ年でも別日なら残る。候補保存・画面操作・問題開始は収集条件に数えず、訪問だけから会議参加・参拝目的・海水浴の実行を推定しない。定義v1のIDと条件を後から変えず、新条件は別定義にする。証拠を失った場合の獲得状況の復元はDBバックアップに依存する。

日本時間を使用。春3〜5月、夏6〜8月、秋9〜11月、冬12〜翌2月。冬の年度は12月が属する年。問題版は `年.1`、問題IDにも年度・季節・難易度を含む。翌年のカタログ生成で以前のゲームや記録を削除しない。季節・年度の変わった未完了問題は採点しないが、完了済みの回答再送は以前の結果を返す。

得点は初級100・上級200からヒント20点、不正答1回5点を引き、最低10点。時間の速さは採点しない。ヒントは一度だけ減点。同一ゲーム版の各利用者の最高点のみをランキングへ掲載し、同点は同順位。公開名は全員「旅人」で識別子は出さない。ランキングの公開範囲は同じローカルサーバー内。参加を選ぶ設定と利用者ごとの表示名編集は未実装。

会議の候補時間は `会議館から徒歩往復＋体験＋10分の余裕`。最大240分。今の季節は現在の出発時刻で往路到着・体験終了・営業日を検証する。海辺は火曜休み。将来季節は旅の候補であり今日行ける場所とは扱わず、出発前に開催日・営業時間を確認する文言を付ける。天候・潮汐・当日の臨時休業・移動個人差はこの架空設定からは確認できない。人生行事の `season=all` は通年の候補。

## バックアップ・復元

SQLiteのオンラインbackup APIを使う。WAL使用中のDB本体だけをコピーしない。

```powershell
..\.venv\Scripts\python.exe -m app.backup ../backups/journal-20261109.sqlite3
```

既存の出力ファイルには上書きしない。DB整合性と外部キー整合性を確認する。バックアップには認証用情報と旅の記録を含むため、個票・セッションを外部へ配布しない。

復元時はサーバー/コンテナを停止し、現在のDBと同名の `-wal` / `-shm` を一緒に別のPJ内退避先へ保全してから、バックアップを `APP_DB_PATH` へ配置する。稼働中DBへ上書きしない。再起動でスキーマ版を確認し、旅の手帳・候補・実績・収集状況・選んだしるしを照合する。テストはbackup出力から別アプリを起動し、同じセッションで全履歴を照合する。SQLite backup APIは全DBを対象にするため `collection_preferences` も含む。

スキーマは `PRAGMA user_version=3`。初版1からは既存履歴を残したまま復旧コードテーブルと収集設定テーブルを追加し、版2からは収集設定テーブルを追加する。未知の版は起動拒否する。今後のスキーマ変更は版ごとの移行を追加し、移行前バックアップと復元確認を必須にする。将来の任意スキーマの移行を保証しない。

## セキュリティ・検証範囲

パラメーター化SQL、外部キー、一意制約、BEGIN IMMEDIATE、WAL、synchronous FULLを使用。APIのDBエラーは内部情報を出さず503。入力エラーは内容を反射せず日本語422。セッション情報はログに出さない。公開は明示した応答モデルの列のみ。静的配信は指定ルートの外や隠しファイルを拒否し、未知APIへHTMLを返さない。

CSPは自己配信だけを許可し、inline script/styleは禁止。nosniff・frame拒否・referrer抑制・不要なデバイス権限抑制を設定。書込本文16KiB、読取10秒、IPごと書込120回/分、新規/既存session POST合計20回/分、復旧は5回/分。頻度制限は単一プロセスのメモリーに保持し、再起動でリセットされる。複数workerやネット公開の分散レート制限を満たすものではない。

`tests/test_api.py` は主な正常系、二重・同時送信、越権、改ざん、CSRF/Origin/Host、DB障害rollback、整合性、復元、季節・年・日付境界、時間計算、休業、保存だけでは実績が増えないことを確認する。依存差替えの時計で境界を検証し、試験専用の公開APIは作らない。自動試験だけで認証取得、全攻撃への耐性、実際の再訪率向上を主張しない。

`tests/test_collection.py` は収集GETの無更新、12種類・セットの最終条件、段階の初回取得日時、別日と同日の区別、過年度の保持、所有者分離、targetの入力検証とCSRF、DB失敗の原子性、復旧・バックアップ・版2移行を確認する。最新の主担当実行記録は `../artifacts/backend-tests.txt` の **51件成功、10.57秒**。収集機能追加直後の50件成功は `../artifacts/backend-tests-collection.txt` に残る途中結果であり、最新版の件数と混同しない。

独立レビューは `../docs/COLLECTION-REVIEW.md` に記録した。レビュー担当自身の軽量確認16群・対象テスト3件と、主担当による51件全体試験を区別する。Docker・ブラウザーの結合結果は `../docs/ACCEPTANCE.md` を参照する。

収集設計は公式資料を確認した6サービス・7機構から、セット、段階、次の行動、具体的な取得記録を採用したもの。12記念品・3棚と目標保存は、既存の再訪2戦略を体験の条件と記録で結ぶ追加機能である。実利用者が以前より面白いと感じるか、実際の再訪が増えるかは未測定。
